# SC 4.1.2 Name, Role, Value

- Standard: WCAG 2.2, W3C Recommendation 12 December 2024
- Level: A
- Principle and guideline: 4 Robust / 4.1 Compatible
- Tier 1 source: https://www.w3.org/TR/WCAG22/#name-role-value
- Tier 2 source: https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html
- Also in: WCAG 2.0 and 2.1, same level
- Verified against the live source: 2026-10-22 by Claude Code, confirmed by direct fetch of the Recommendation page

## Normative text (tier 1, quoted)

> For all user interface components (including but not limited to: form elements, links and components generated by scripts), the name and role can be programmatically determined; states, properties, and values that can be set by the user can be programmatically set; and notification of changes to these items is available to user agents, including assistive technologies.
>
> Note: This success criterion is primarily for web authors who develop or script their own user interface components. For example, standard HTML controls already meet this success criterion when used according to specification.

## What it requires, in our words

Every interactive thing on the page must tell assistive technology three things: what it is called, what kind of thing it is, and what state it is in. Native HTML controls do this on their own when used as specified, which is why the note points at authors of custom components. The requirement bites hardest on inputs with no label, buttons that are only an icon, links that are only an image, and custom widgets built from generic elements. How the name is computed is governed by the Accessible Name and Description Computation specification, not by this criterion.

## How it fails in code

- A text input with no `label`, no `aria-label`, no `aria-labelledby`, and no `title`. Visible text sitting beside the input does not count unless it is associated. Definite.
- A button whose only content is an icon, image, or SVG with no accessible name. Definite.
- A link whose only content is an image with empty or missing alt text. Definite.
- A clickable `div` or `span` acting as a button or link with no role. Definite.
- A custom checkbox, toggle, tab, or expandable region that changes state visually without exposing that state (`aria-checked`, `aria-pressed`, `aria-selected`, `aria-expanded`). Definite when the state is user-settable.
- A placeholder as the only label. A name may be computed from it, but the text disappears on input and the pattern also touches SC 3.3.2. Report as likely and cross-reference 3.3.2 (no entry yet).
- An element with a role whose name is present but meaningless, such as "button" or "click here". Manual review; the name exists, so this criterion is met, but SC 2.4.4 or 2.4.6 may not be (no entries yet).

## How to meet it

- Native HTML first. A `label` element associated with the control, a `button` element with text, an `a` element with text, native `input` types. Technique H91, "Using HTML form controls and links".
- Technique H44, "Using label elements to associate text labels with form controls".
- Technique ARIA16, "Using aria-labelledby to provide a name for user interface controls", when the visible text is elsewhere on the page.
- Technique ARIA14, "Using aria-label to provide an accessible name where a visible label cannot be used".
- Technique H65, "Using the title attribute to identify form controls when the label element cannot be used". Last resort; title is not reliably announced everywhere.
- Technique G108, "Using markup features to expose the name and role, allow user-settable properties to be directly set, and provide notification of changes", for custom components.

All techniques are tier 2, from https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html, which lists them as sufficient.

## Related criteria

- SC 1.3.1 Info and Relationships (no entry yet). Often cited alongside for unassociated labels.
- SC 3.3.2 Labels or Instructions (no entry yet). Whether a label exists at all, as distinct from whether it is programmatically attached.
- SC 2.4.4 Link Purpose (In Context) and 2.4.6 Headings and Labels (no entries yet). Whether the name is meaningful.
- Accessible Name and Description Computation 1.2, tier 1, https://www.w3.org/TR/accname-1.2/, for how the name is derived.

## Automated coverage (tier 3)

It cannot judge whether a name is meaningful, and it cannot tell whether a custom widget's state updates when the user acts.
